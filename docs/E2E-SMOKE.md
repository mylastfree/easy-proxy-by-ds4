# 真实浏览器 E2E 冒烟清单

> 【M-4·审计修复】单元/护栏测试全部依赖手写 chrome mock，真实浏览器的行为差异
> （chrome.proxy 语义、存储配额、SW 生命周期）不在其覆盖范围内。本清单是发布前
> 的最低限度人工冒烟：每次发布（版本号变更）前逐项执行并勾选，全部通过才打包。
>
> 环境：Chrome 稳定版（不低于 manifest 的 minimum_chrome_version），普通窗口 +
> 隐身窗口各验证一次关键项。

## 第 0 步（必做）：先跑自动化的那部分

> 【M-3·审计修复】审计把「真实浏览器 E2E」列为**唯一的上线前置条件**，理由是
> 788 项断言全部跑在 `chrome.*` 替身之上。`tests/e2e-smoke.js` 已把其中**结论性最强、
> 最不依赖人为观察**的三条主干脚本化（22 项断言，Playwright 驱动真实 Chromium 加载
> **打包产物**）：

```powershell
npm run e2e        # 退出码 0 = 通过；1 = 真实缺陷；2 = 环境未就绪（不计为失败）
# $env:E2E_HEADLESS=1                        # 无头模式
# $env:E2E_CHROME_PATH="C:\...\chrome.exe"   # 指定浏览器
```

| 自动化覆盖 | 断言要点 |
| --- | --- |
| ① 启用 → 生效 | `levelOfControl === controlled_by_this_extension`、`mode === fixed_servers`、`singleProxy` 与设置逐字段一致、`lastState.status === applied` |
| ② 禁用 → 未残留 | 未残留本扩展的 `fixed_servers`、回读签名**完全回到测试前基线**、`status === direct`、实际模式非 `direct` 时如实上报 `systemProxy` |
| ③ 外部接管 → 不夺权 | 第二个扩展写入 `fixed_servers` 后落 **`overridden` 而非 `applied`**，生效配置仍是接管者的（不夺权） |

**下面是自动化无法覆盖的残余项**，仍需人工逐项执行：自动化只断言
「状态结论与控制权归属是否正确」，而**真实流量是否走了代理**（连通性、出口 IP
是否变化、绕过列表是否真的直连）、**安装/升级路径**、**隐身窗口**、**存储配额**
这四类只能靠人工观察。

## 准备

- [ ] 本地代理可用（如 127.0.0.1:10808 的 SOCKS5 / HTTPS 代理），可访问外网
- [ ] `node tools/package.js` 产出 dist/，以「加载已解压的扩展程序」加载 dist 目录
- [ ] 打开 chrome://extensions 确认无报错（service worker 处于活动状态）

## 安装与升级

- [ ] 全新安装：打开 popup，全部字段为默认值；开关默认关闭
- [ ] 卸载后重装（同一账号）：云端已有配置不被默认值覆盖（V-04 真实验证）
- [ ] 覆盖旧版本目录升级：用户已填地址/端口/绕过列表原样保留

## 启用与生效

- [ ] 填入代理地址端口，启用，保存 → 图标转绿，状态条显示「代理已生效」
- [ ] **真实流量验证（自动化不做）**：访问 `https://ipinfo.io/json` 等站点，确认出口 IP
      已变为代理服务器出口，而不是仅状态条宣称已生效
- [ ] 连接测试「测试当前出口」→ 出口为代理服务器出口；界面出现第三方出口知情提示
- [ ] 「对比直连出口」→ 直连出口与本机网络一致，对比后配置自动恢复
- [ ] 绕过列表填 `.lan`，访问内网地址直连生效
- [ ] **灰度/色觉验证（L-7）**：状态条在灰度截图下仍可分辨 —— 每个状态都必须带严重度
      符号（`✓` / `⚠` / `✗` / `·`），不能只靠颜色

## 禁用与接管

- [ ] 关闭开关 → 图标变灰/红，状态「未启用代理（直连）」；网页可正常访问
- [ ] **禁用后的真实直连验证（自动化不做）**：确认流量确实回到本机网络（出口 IP 复原）
- [ ] 用另一个扩展（如 Proxy SwitchyOmega）接管代理 → 本扩展显示「被外部接管」，
      不发生夺权；本扩展未启用时点保存/开关亦不得清掉对方的配置
- [ ] 删除接管方扩展 → 本扩展控制权恢复，界面状态如实刷新

## 边界与异常

- [ ] 填入非法值（空端口、`example.com:8080:90`、超范围端口）→ 保存被拒绝并如实提示，
      图标不转绿
- [ ] 粘贴超过 8KB 的超长绕过列表 → 提示「已存于本地（不跨设备同步）」，重开 popup
      列表仍在；随后关闭代理 → 长列表不丢失
- [ ] 停掉代理软件 → 连接测试报错如实呈现，图标转红；恢复代理软件后重测恢复
- [ ] 隐身窗口（`chrome.proxy` 的 incognito 语义与普通窗口不同）：普通窗口 ↔ 隐身窗口
      各验证一次启用/禁用，确认两边结论一致、无遗留作用域
- [ ] 开发者工具中确认：`chrome.storage.local` 只有预期键；无 `eval`/远程代码加载

## 收尾

- [ ] 移除扩展：设置随扩展清除，浏览器代理恢复系统默认（chrome://settings 确认）
- [ ] 全部通过后：`git tag v<version>` 前再跑一次 `npm run mutation` 与 `npm run e2e`
